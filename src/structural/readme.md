# Structural Design Patterns

## Definition
Structural design patterns describe how classes and objects can be combined to build larger, flexible, and maintainable software structures. They organize relationships between components without changing their core responsibilities.

## Purpose
- Organize classes and objects into reusable structures.
- Reduce tight coupling between components.
- Make systems easier to extend and maintain.
- Simplify how different parts of an application work together.

## Problems They Solve
Structural patterns help address common design problems:
- **Incompatible interfaces:** connecting components that cannot work together directly.
- **Complex object structures:** organizing individual objects and groups consistently.
- **Tight coupling:** reducing direct dependencies between components.
- **Adding responsibilities:** extending an object's behavior without modifying its original class.
- **Complex subsystems:** providing a simpler way to interact with many components.
- **Uncontrolled access:** managing access to an object or resource.

## Common Structural Patterns

| Pattern | Main Idea |
|---|---|
| Adapter | Makes incompatible interfaces work together. |
| Bridge | Separates an abstraction from its implementation. |
| Composite | Treats individual objects and groups uniformly. |
| Decorator | Adds responsibilities to an object dynamically. |
| Facade | Provides a simple interface to a complex subsystem. |
| Flyweight | Shares objects to reduce memory usage. |
| Proxy | Controls access to another object. |

## Advantages
- Improves code reuse and flexibility.
- Reduces coupling between classes.
- Makes complex structures easier to understand.
- Supports extension with fewer changes to existing code.
- Improves maintainability and scalability.

## When to Use
Use structural patterns when you need to connect components, simplify complex object relationships, or build software structures that are easier to change and maintain.
